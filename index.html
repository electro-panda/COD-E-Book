Preface & Course Scope

Pedagogical Approach

This textbook provides a rigorous physical and logical breakdown of modern computing machinery. Computer architecture serves as the operational contract between low-level hardware design and high-level software abstraction.

Moving systematically from basic digital logic up through complex processor datapaths, control mechanisms, instruction pipelines, and memory hierarchies, this reference equips computer applications scholars with complete circuit schematics, architectural models, and quantitative performance formulas.

Module Structure

  • Module 1: Logic Gates & Combinational Circuits — Boolean foundations, adders, subtractors, multiplexers, decoders, and sequential elements.
  • Module 2: Central Processing Unit Architecture — Register Transfer Language (RTL), ALU design, micro-operations, bus configurations, and instruction cycles.
  • Module 3: Control Unit & Pipeline Execution — Hardwired vs. microprogrammed control, 5-stage MIPS pipelines, and hazard handling.
  • Module 4: Memory & I/O Organization — Memory hierarchies, cache mapping, virtual memory address translation, and Direct Memory Access (DMA).

MODULE 1 · ARCHITECTURAL FOUNDATIONS

Architecture vs. Organization

Computer Architecture defines the high-level operational specification visible to assembly language programmers — instruction sets, data word sizes, memory addressing modes, and CPU registers.

Computer Organization describes the structural implementation of these specifications at the hardware gate level — control signals, internal bus topologies, memory interfaces, and ALU layouts.

System Models: Von Neumann vs. Harvard

Figure 1.1: Shared vs. Separate Memory Bus Topologies

The Von Neumann bottleneck arises because instruction fetches and data read/writes must share a single bus sequentially. Harvard systems circumvent this by decoupling instruction and data buses.

Boolean Algebra & Gates

Digital hardware evaluates binary signals via Boolean logic. Fundamental logic gates form the building blocks of both arithmetic units and high-speed memories.

Figure 1.2: Standard IEEE Primitive Logic Gate Symbols

Core Boolean Theorems

De Morgan's Laws:   (A · B)′ = A′ + B′   |   (A + B)′ = A′ · B′
Distributive:       A + (B · C) = (A + B) · (A + C)
Absorption:         A + (A · B) = A        |   A · (A + B) = A

Adders & Subtractors

A Half Adder computes the sum of two single binary inputs A and B, generating a Sum (S) and Carry-out (C).

Sum = A ⊕ B   |   Carry = A · B

Full Adder Circuit & Truth Table

A Full Adder incorporates an incoming Carry-in (Cin), allowing multi-bit addition by chaining stages sequentially.

Carry Lookahead Adder

Standard ripple-carry adders incur O(N) propagation delay because carry bits must trickle through all bits. A Carry Lookahead Adder (CLA) eliminates this bottleneck by precomputing carry signals in parallel.

Generate & Propagate Functions

Carry Generate:  G_i = A_i · B_i
Carry Propagate: P_i = A_i ⊕ B_i
Stage i Sum:     S_i = P_i ⊕ C_i
Next Carry:      C_{i+1} = G_i + P_i · C_i
Figure 1.3: CLA Parallel Carry Expansion Logic

Unrolling carry expansion yields independent equations:

C1 = G0 + P0·C0
C2 = G1 + P1·G0 + P1·P0·C0
C3 = G2 + P2·G1 + P2·P1·G0 + P2·P1·P0·C0

Demultiplexers & Decoders

A Demultiplexer (DEMUX) performs the inverse function of a MUX: it takes a single data input and routes it to one of several output lines selected by address inputs.

3-to-8 Line Decoder

A decoder converts an n-bit binary input code into a maximum of 2^n unique output lines. Memory arrays rely heavily on decoders for row and column address selection.

Figure 1.5: 3-to-8 Line Decoder with Enable Control Line

When Enable (E) is deactivated, all decoder output lines remain 0 regardless of input variables A0-A2.

Priority Encoders

An Encoder carries out the inverse operation of a decoder, compressing 2^n input lines into an n-bit binary output code.

If multiple inputs become active simultaneously, standard encoders generate invalid codes. A Priority Encoder resolves this conflict by establishing a strict priority hierarchy.

0 0 0 1 0 0 1
0 0 1 X 0 1 1
0 1 X X 1 0 1
1 X X X 1 1 1

Latches & Flip-Flops

Sequential logic circuits rely on memory elements whose output states depend on both current inputs and previous history. A Latch is level-triggered, whereas a Flip-Flop is edge-triggered.

When both inputs are high in standard level-triggered latches, race-around conditions occur. The Master-Slave JK Flip-Flop resolves this by cascading two latches driven by complementary clock pulses.

MODULE 1 · REGISTERS

Shift Register Systems

A Shift Register is a cascaded arrangement of flip-flops sharing a common clock. It shifts multi-bit binary data laterally from one stage to the next per clock cycle.

I/O Operational Categories

  • SISO — Serial-In, Serial-Out (Delay lines).
  • SIPO — Serial-In, Parallel-Out (Serial communication convertor).
  • PISO — Parallel-In, Serial-Out (Data serialization).
  • PIPO — Parallel-In, Parallel-Out (CPU register storage).

4-Bit Universal Shift Register (USR)

Figure 1.8: Cascaded Flip-Flop Register Array

Control lines (S1, S0) select USR operation: 00 → Hold, 01 → Shift Right, 10 → Shift Left, 11 → Parallel Load.

MODULE 1 · REGISTERS

Counter Circuit Design

A Counter is a specialized sequential circuit that transitions through a prescribed sequence of states upon receiving clock pulses.

Asynchronous vs. Synchronous Counters

Asynchronous (Ripple)
Output of one stage triggers the clock line of the next stage. Simple design, but propagation delay accumulates across bits.
Synchronous
All flip-flops share an identical clock pulse line simultaneously. Eliminates ripple delays, supporting high clock frequencies.

4-Bit Synchronous Up-Counter Logic

Modulo-N counters cycle through N states before resetting to zero (N = 2^n for an n-bit counter).

Register Transfer Language

Register Transfer Language (RTL) is a symbolic notation used to specify internal hardware micro-operations and register transfers.

Conditional Control Execution

P: R2 ← R1       // If control signal P=1, transfer contents of R1 to R2
T1: MAR ← PC    // Move Program Counter to Memory Address Register
Figure 2.1: Clock-Synchronized Register Transfer

Primary Micro-operation Classes

  • Register Transfer — Moves binary data between registers.
  • Arithmetic — Executes binary Add, Subtract, Increment, Decrement.
  • Logic — Executes bitwise AND, OR, XOR, Complement operations.
  • Shift — Shifts register data left or right.

Common Bus System Architecture

Interconnecting N registers using point-to-point wiring requires O(N^2) connections. A Common Bus Structure reduces this complexity by sharing a unified bus pathway across registers via Multiplexers or Tri-State Buffers.

Figure 2.2: Multiplexer-Based Common Bus Interconnect

Tri-State Buffer Bus Interconnect

Tri-state gates output three states: Logic 0, Logic 1, and High-Impedance (Z), enabling direct wired-bus connections without multiplexer overhead.

CPU Bus Architectures

The internal arrangement of CPU buses determines how many data transfers can occur in parallel per clock cycle.

Single-Bus CPU Architecture

All registers and the ALU share a single internal path. Low hardware cost, but arithmetic operations require multiple clock cycles to sequentially load operands into temp registers.

Triple-Bus CPU Architecture

Buses A and B feed both ALU inputs simultaneously, while Bus C writes results back to registers in a single clock cycle.

Instruction Pipelining

Pipelining increases CPU instruction throughput by overlapping execution stages across successive instructions, mimicking an assembly line.

Standard 5-Stage MIPS Pipeline

Figure 3.3: MIPS 5-Stage Hardware Execution Pipeline

Performance & Speedup Metrics

Theoretical Speedup (S_k) = (n · k) / (k + n - 1)
For large n: S_k ≈ k (Number of pipeline stages)

Where k represents pipeline stages, and n represents total executed instructions.

MODULE 3 · PIPELINING

Pipeline Hazards

Pipeline hazards prevent the next instruction from executing in its designated clock cycle, introducing pipeline stalls or "bubbles".

Primary Hazard Classifications

  • Structural Hazards — Resource conflicts when two stages require the same hardware block simultaneously.
  • Data Hazards — Arise when an instruction depends on results of a prior instruction still in flight (RAW, WAR, WAW).
  • Control Hazards — Delays caused by conditional branch instructions.

MODULE 4 · MEMORY SYSTEMS

Cache Memory Principles

Cache memories operate on the Principle of Locality, buffering frequently accessed data slices near the CPU core.

Locality Classifications

  • Temporal Locality — Data accessed recently is likely to be accessed again in the near future (e.g., loop counters).
  • Spatial Locality — Data stored near recently accessed addresses is likely to be accessed soon (e.g., array traversals).

Average Memory Access Time (AMAT)

System memory performance is evaluated using the weighted average formula:

AMAT = Hit Time + (Miss Rate × Miss Penalty)
Example Calculation
Given Hit Time = 1 cycle, Miss Penalty = 50 cycles, and Hit Rate = 95% (Miss Rate = 0.05):
AMAT = 1 + (0.05 × 50) = 3.5 Clock Cycles

MODULE 4 · MEMORY SYSTEMS

Cache Mapping Techniques

Main memory addresses are mapped to cache locations using three primary hardware mapping schemes:

1. Direct Mapping

Each main memory block maps to exactly one specific cache line determined by index calculation.

Cache Line Index = (Block Address) Mod (Total Cache Lines)
Figure 4.2: Direct Mapped Cache Address Field Partitioning

2. Fully Associative Mapping

Any main memory block can reside in any cache line. Eliminates conflict misses completely, but requires parallel search comparators for all tag entries.

3. Set-Associative Mapping

Combines direct and associative mapping. Cache is divided into sets of K lines (e.g., 2-way, 4-way, 8-way).

Set Index = (Block Address) Mod (Total Number of Sets)

MODULE 4 · MEMORY SYSTEMS

Virtual Memory & TLB

Virtual Memory provides an abstraction that gives each process the illusion of a large, contiguous memory space by mapping virtual addresses to physical RAM or secondary disk storage via fixed-size blocks called Pages.

Address Translation & Page Table

The Memory Management Unit (MMU) translates a Virtual Page Number (VPN) into a Physical Frame Number (PFN) using a Page Table in main memory.

Figure 4.3: Virtual-to-Physical Address Translation via TLB

Translation Lookaside Buffer (TLB)

The TLB is a high-speed associative cache inside the MMU storing recent VPN-to-PFN mappings, reducing page table access penalty from two memory accesses down to one clock cycle.

Page Fault Handling
A Page Fault occurs when the referenced page is not resident in physical RAM (Present Bit = 0), triggering an OS trap to fetch the page from disk into RAM.

MODULE 4 · INPUT/OUTPUT ORGANIZATION

I/O & Direct Memory Access

Input/Output subsystems bridge the high-speed CPU/Memory bus with peripheral devices operating at disparate transfer rates.

I/O Transfer Modes

  • Programmed I/O — CPU continuously polls device status bits (high CPU overhead).
  • Interrupt-Driven I/O — Device signals CPU via interrupt vector when ready.
  • Direct Memory Access (DMA) — Specialized controller transfers data blocks directly between memory and peripheral without CPU intervention.

DMA Controller Architecture

Figure 4.4: DMA Controller System Bus Interconnect

DMA Transfer Operational Modes

Burst Mode: DMAC takes continuous control of bus for entire data block.
Cycle Stealing: DMAC transfers 1 word per CPU bus cycle opportunity.
Transparent Mode: DMAC transfers data only when CPU is not using bus.
